
El Protocolo de Entrega establece el conjunto de reglas, formatos, tecnologías y canales mediante los cuales los entregables y la información del proyecto son comunicados, distribuidos y validados formalmente con los interesados. 

Dado que el proyecto adopta una metodología incremental ágil (Scrum) con fases de ejecución divididas en Sprints, es indispensable definir claramente la estructura de comunicación para la entrega y validación de cada incremento funcional, involucrando tanto a la entidad cliente (Ministerio de Transporte y Secretarías de Tránsito) como al equipo de desarrollo.

\subsection{Estructura de Comunicaciones y Roles}

Para garantizar el éxito de las entregas parciales y la planificación progresiva del alcance, se define la siguiente estructura de comunicación a tres niveles:

\begin{itemize}
    \item \textbf{Nivel Directivo y de Aprobación (Cierre de Sprint):} 
    \begin{itemize}
        \item \textit{Por parte del cliente:} Director de Proyecto (Ministerio-Secretaría), Supervisor del Contrato y Asesores Técnicos.
        \item \textit{Por parte del equipo de desarrollo:} Project Manager / Scrum Master y Líder Técnico.
        \item \textit{Canal/Evento:} \textbf{Sprint Review} (Reunión de demostración funcional) por videoconferencia. En este espacio se ejecuta la validación formal del incremento y se firman las actas de aceptación parcial.
    \end{itemize}
    
    \item \textbf{Nivel Táctico e Infraestructura (Quincenal o por demanda):}
    \begin{itemize}
        \item \textit{Por parte del cliente:} Coordinadores de TI, Coordinadores Médicos (CRC) y Directores Operativos.
        \item \textit{Por parte del equipo de desarrollo:} Arquitecto de Software, Administrador de Base de Datos, DevOps, Especialista en Seguridad y Coordinador de Integraciones.
        \item \textit{Canal/Evento:} Reuniones técnicas para coordinar integraciones y despliegues. Comunicación asíncrona mediante correos institucionales y grupos específicos de Slack y WhatsApp.
    \end{itemize}
    
    \item \textbf{Nivel Operativo de Desarrollo (Diario):}
    \begin{itemize}
        \item \textit{Roles:} Scrum Master (Project Manager), Product Owner (Analista Funcional) y Equipo de Desarrollo (Frontend, Backend, QA Tester).
        \item \textit{Canal/Evento:} \textbf{Daily Scrum} (Reunión operativa diaria). Control de las tareas del Sprint mediante tableros de gestión ágil (Jira/Trello) y repositorios en GitHub.
    \end{itemize}
\end{itemize}

\subsection*{Consideraciones tecnológicas del protocolo}
\begin{itemize}
    \item \textbf{Control de Versiones y Código:} Todos los incrementos funcionales de software se almacenarán y versionarán obligatoriamente en \textbf{GitHub}.
    \item \textbf{Documentación y Actas:} Se utilizará una carpeta compartida en \textbf{Google Drive} con permisos de lectura-escritura controlados para gestionar el Product Backlog (EDT), actas de Sprint Review y manuales.
    \item \textbf{Gestión de incidentes rápidos:} Se autoriza el uso de herramientas de mensajería instantánea (WhatsApp y Slack) exclusivamente para coordinación operativa. Cualquier decisión que afecte la línea base del alcance requiere aprobación formal documentada.
\end{itemize}
